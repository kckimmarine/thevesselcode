## Q2. 배경 (2000자 이내)

글로벌 대형 선사(Tokyo Marine)에서 1급 기관사로 대형 선박 기관실을 총괄하고, 육상 본사에서 10년간 공무팀장으로서 수십 척의 선박 정비와 안전 관리를 지휘했습니다. 현장에서 매일 마주한 가장 뼈아픈 문제는 ‘아날로그식 주먹구구 관리와 심각한 데이터 단절’이었습니다.

선박은 바다 위에 떠 있는 거대한 복합 플랜트입니다. 하지만 대기업을 제외한 대다수 10~50척 규모 중소형 선사는 여전히 낡은 엑셀 파일이나 수기 장부로 수천 종의 부품과 정비 일지를 관리합니다.

실제 현장에서는 어처구니없는 사고가 반복됩니다. 본선 창고에 보관된 펌프 메카니컬 실(Seal) 재고가 엑셀 장부와 맞지 않아 정비 시점에 부품을 찾지 못했고, 결국 하루 용선 손실(Off-hire)만 수천만 원에 달하는 선박이 출항을 멈추고 긴급 항공 공수 비용까지 발생했습니다. 반대로 이미 선내에 충분히 남아 있는 수백만 원대 밸브 부품을 찾지 못해 중복 발주하여 창고에 쌓아두는 예산 낭비 역시 매년 일어납니다. 이건 특정 선사만의 문제가 아니라, IT 전담 인력이 없는 10~50척 중소형 선단의 공통 패턴입니다. 더욱이 국제해사기구(IMO)와 ISM Code 규정상 유지보수 기록의 추적성 실패는 선박 결함 지적으로 이어져 곧바로 운항 정지와 막대한 재정적 책임으로 직결됩니다.

기존 외산 선박관리 솔루션은 초기 구축비만 수억 원대에 달하고, 고가의 상시 위성망을 전제하여 중소 선사는 도입할 엄두조차 내지 못했습니다.

“선박은 인터넷이 끊겨도 100% 오프라인으로 돌아가고, 선장과 육상 공무감독은 가벼운 표준 압축 파일(ZIP)로 데이터를 맞추며, 부품 견적과 수리까지 한 흐름으로 연결하는 실용적인 전용 플랫폼이 반드시 필요하다”는 절실함에서 본 프로젝트를 시작했습니다.

## Q3-1. 차별점 (2000자 이내)

**1. 타깃 고객**  
자체 IT 전산망 구축 여력이 없어 엑셀과 수기 장부에 의존하던 국내외 10~50척 규모의 중소형 선사, 선박관리사(SM), 승선 해기사, 그리고 선용품/수리 협력사.

**2. 3모드(SM / Vessel / Supplier) 연계 아키텍처 및 핵심 차별점**  
기존 외산 PMS가 수억 원대 구축비와 복잡한 UI, 상시 인터넷을 요구했던 것과 달리, 더베슬코드는 **중소형 맞춤·저도입 비용·오프라인 우선**으로 해운 업무를 3개 모드로 유기적으로 연결했습니다.

- **Vessel Mode (선박 현장 - 오프라인 완결 구동):** 기관부(ECR)와 갑판부(CCR)는 위성 통신이 두절되는 대양 항해 중에도 로컬(IndexedDB) 기반으로 PC·모바일에서 정비(PMS), 자재(SPARE), 결함(Defect)을 100% 오프라인 완결 기록합니다. 정비 보고 확인(Confirm) 시 투입된 기부속 재고가 즉시 자동 차감되는 자체 검증 로직을 탑재해 데이터 중복 차감과 불용 재고 누수를 원천 차단합니다.

- **Vessel Captain Hub & 하이브리드 ZIP 패킷 동기화:** 선장(Captain Hub)은 기관·갑판의 정비 보고를 통합 취합하며, 선박과 육상 본사 간 데이터 동기화는 값비싼 상시 위성망 대신 변경분만 담은 표준 압축 파일(ZIP) 패킷을 이메일·USB·메신저로 안전하게 교환합니다.

- **SM Mode (육상 - 온라인 관제):** 본선 ZIP Import로 다선박 관제, Class·PSC 검사 대응 패키지 Export, RFQ Case 생성 및 Supplier 전달.

- **Supplier Mode (협력사 - 온라인 포털):** RFQ 확인, 견적 회신, Delivery/Repair·Invoice 연계 B2B 파이프라인.

- **15,000+ IMPA 및 Maritime Toolkit:** 15,000건 이상 검증 IMPA 규격·도판과 실무 툴킷(thevesselcode.com/toolkit).
